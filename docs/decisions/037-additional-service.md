# 037 — "Requires additional service" (Levan, 2026-11-15)

**Context.** Some services need a second one later the same visit: hair colouring, then wash and blow-dry about two hours later. The specialist should be free in between to take other clients.

**Decision.** A service can name one additional service and "after X minutes" (`services.followup_service_id`, `followup_after_min`, default 120, 0–720; same-business foreign key, cleared if that service is deleted). Staff booking only: when the main service is picked in "New booking", a reminder card appears with "Add to this visit" switched on, the suggested time (end of the first services + X) and the specialist (same person if they do it). Both are saved as **one visit** (one booking, two items with their own start times): one SMS, moved and cancelled together. Repeated bookings skip it. **Online booking stays as it is** (Levan chose the lighter option): the client books only the main service; the calendar marks such visits "Additional service not added", the booking panel adds it by hand (`add_booking_item`, same snapshots and overlap rule), and future online visits show a computed bell notice `needs_followup` that disappears once it is added.

**Consequence.** The database already allows a gap between items (overlap is checked per item), so no change there. The server checks the additional part on its own time (hours, other bookings, it must start after the first part). The calendar shows one block per continuous part; dragging either part moves the whole visit and keeps the gap; moving checks each part separately. Resizing by the bottom edge changes only that part's block (as before, the last item).
